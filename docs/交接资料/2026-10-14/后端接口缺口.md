# 给后端组员的对齐清单

当前代码基于 631eca0，前端已有本地改动。这里描述原型与后端的差异，不表示已实现的新接口。

| 原型能力 | 当前后端 | 需要对齐 |
|---|---|---|
| B01–B04 核对后保存/仅本次使用 | enabled开启后每轮自动生成并保存摘要 | 新候选与确认提交合同，逐轮保存许可；默认不写候选 |
| B05 分类生活事件、状态、年月 | 存text/problem/user_state/problem_status，非结构化事件 | 事件类型、时间精度、category、source、ID与计数 |
| B06 显示实际使用记忆 | cards.memory_ids、match_reason已返回，但无单独本轮usedMemory对象 | 真实用到的ID和说明，不把全部有效记忆当本轮使用 |
| B08/B09 事件编辑与新旧冲突 | correct_summary整体纠正摘要，revision使旧运行失效 | expectedVersion、同事件合并、冲突返回；避免重复创建 |
| B13 使用/保存两个开关 | enabled一个开关，同时控制读写 | allowUse/allowSave独立契约及在途任务规则 |
| A03/A10 流式与停止 | /api/run一次性JSON，取消客户端请求不取消模型 | 经过校验的流式协议与服务器取消回执 |
| A12 重新生成保留旧版 | 无回答版本、重新生成接口 | answerVersions、turnId、重新生成保存规则与幂等 |
| S07/S11 最近话题与恢复历史 | 只有长期摘要和短期6轮内存，无会话历史读取接口 | 会话列表、消息分页、存储/删除政策 |
| A02/A09 当前情境识别与修正 | 无结构化情境对象/修正接口 | confirmed/unknown字段、来源与按本次修正 |
| S04/C04 Radar推荐 | home只回访问题，不返回建议正文 | 候选推荐ID、原文guide_id、memory依据、有效版本 |
| C03原始来源核验 | 返回固定指南source_url/fields；不实时访问来源网页 | 不要把返回链接称为来源实时核验成功；可明确无法访问 |
| C14/C15 推荐更新状态 | 无异步推荐任务/更新ID | 更新状态、旧结果保留、重试幂等 |
| D模块关注反馈与事实变化 | feedback仅guide_id+kind；记忆关闭拒绝长期feedback | 区分关注偏好、已完成、个人事实更正；不能一键改变记忆事实 |
| 单条删除影响 | store.delete同时清理该用户全部feedback | 与原型局部删除语义对齐，是否需要收窄清理范围 |

已有feedback枚举为 not_interested/done/ineffective/undo；只表示对指南反馈，不能视为每个生活事件已解决或不再发生。前端会先实现清晰标注的mock交互，真实模式保持现有能力并明确缺口。

新合同请至少提供合成请求/响应、错误码、身份归属、revision/version、幂等request_id，以及取消/重复提交是否真的生效。Proma核心来源和接入层也请明确，前端不持有模型Key。
