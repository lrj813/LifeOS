## 4. 第一版范围与模式

### 4.1 原型模式（默认交付）

通过独立模拟服务演示完整流程。明显但简短地标注“交互演示 · 模拟数据”，避免用户误以为真实 AI 已连接。使用可选择的验收场景驱动状态，不用输入关键词才能触发所有功能。假数据需要覆盖空态、正常、等待、失败、纠正、冲突和恢复。

模拟服务要真的维护状态：保存后列表和计数变化、更新后同一事件保持 identity、删除后失效、关闭调用后不再引用、仅本次信息不进入长期档案。不能做只换文案的静态假按钮。默认逐字聊天在内存；若演示确需浏览器持久化，只持久化明确的虚构数据，按账号隔离，提供重置，不自动保存用户真实输入。

### 4.2 真实接口模式

保持原有账号 Cookie 验证及真实问答、指南来源、摘要开关、纠正、删除、回访能力。使用真实 `/api`。登录仍是调用受保护 API 的前提，可在登录前浏览介绍与引导，不承诺匿名真实问答。

能力缺失时用 capability gating：隐藏或明确禁用新操作，并说明“此功能待接口接入”。不要把候选事件确认 UI 接到自动摘要保存后假装“未确认就未保存”。真实模式记忆设置显示“自动摘要与长期记忆读写”的现有总开关，独立开关只在原型模式开放。

两种模式共用页面组件和 ViewModel，但服务实现明确分开；切换时重置请求、账号、消息、候选信息和编辑状态。正式构建不加载 fixture、preview 模拟模块或验收控制面板。

### 4.3 后续范围

最终配色、字体、插画、动效、复杂过渡、真实流式协议、服务器取消、正式账号注册、跨设备历史、自动 Radar 推荐与真实推荐反馈闭环留到接口/UI 明确后。不要自行接第三方搜索或泛化生活建议来源。

## 5. 页面与核心状态

原型是状态图，不是每个 S/A/B/C 编号单独一个路由。建议 `#/today`、`#/agent`、`#/life`、`#/settings`；欢迎/引导作为首次进入的子状态。路由参数不放隐私正文、凭据或用户 token。浏览器返回键可回到合理页面，不把编辑中的输入丢掉。

应用共同状态建议：

```text
app = { mode, capabilities, account, sessionEpoch, route,
        onboardingCompleted, homeState, activeConversationId,
        draftByConversation, messages, currentContext,
        pendingCandidate, events, memorySettings, recommendations,
        requestState, modalState }
```

- `messages`：用户/助手文本、状态、版本、来源卡片；各 turn 独立，不替换整个聊天区域。
- `currentContext`：只包含当前对话明确提供或确认的信息；同“已保存记忆”分开。
- `pendingCandidate`：尚未提交的可编辑候选生活事件，不参与其他会话个性化。
- `events`：用户确认保存的结构化事件，不能直接拿所有聊天摘要冒充。
- `memorySettings`：原型模式 `{allowSave, allowUse}`；真实模式当前只有 `{enabled}`。
- `requestState`：`idle/submitting/waiting/responding/stopped/failed/completed`；当前真实接口只有 submitting/waiting/completed/failed，不能假造真实 streaming 状态。

## 7. 已有真实 API（不可把新增建议当已有）

全部同源请求；正式前端 Cookie `credentials:'same-origin'`。后端内部 token 不进入前端，模型 Key 不进入响应。真实端同用户模型请求串行；409提示上一轮仍在处理。请求体上限20KB。

| 方法 / 路径 | 请求 | 响应与用途 |
|---|---|---|
| GET `/health` | 无 | `model.configured`只证明配置可解析，不能作为真问答成功证明 |
| POST `/api/login` | `{username,password}` | `{user:{id,name}}`，设置8小时HttpOnly Cookie |
| POST `/api/logout` | `{}` | 撤销当前会话，前端清除显示和epoch |
| GET `/api/me` | 无 | `{user:{id,name}}`；401清理账号私有UI |
| GET `/api/memories` | 无 | `{enabled,revision,memories,effective,feedback}`；真实长期摘要 |
| POST `/api/memory-action` | 见下文 | 现有 settings/correct_summary/delete/clear/feedback |
| POST `/api/run` | `{mode:'chat'|'home',query,conversation_id,followup_memory_id}` | 一次性JSON，不是SSE/WebSocket |
| GET `/api/guide-entry?guide_id=03-01` | 无body | 指南完整条目。必须登录 |

## 8. 新服务门面与后端缺口

以下是**建议的前端服务抽象**，不是已存在的HTTP路径。首版给 mock provider 实现；real provider遇到未支持能力返回明确 capability 不支持，不能发向猜测接口。

需要后端同学确认的合同：

1. **确认保存**：候选提取与回答分离，默认不自动写新长期事件；确认保存接口返回已提交实体。scope=this_conversation不写长期库。
2. **事件数据**：至少id/category/type/status/date精度/sourceMessage/version/createdAt/updatedAt；按分类枚举及计数读取。摘要不是事件字段的可靠替代。
3. **更新冲突**：expectedVersion/revision校验、返回冲突与最新值、幂等request_id；不能用最后提交盲覆盖。
4. **独立开关**：allowSave与allowUse分别生效，并说明对正在运行任务的影响。
5. **历史会话**：列表、消息分页、消息ID与回答版本；存储政策由团队确定，不能用长期摘要伪造逐字历史。
6. **流式/取消/再生成**：有校验后的chunk协议、结束与保存状态、服务器取消回执、幂等与原回答版本保存。未返回完整合法指南前不展示未核对建议。
7. **推荐/反馈**：推荐ID、来源guide_id、依据memory_id、有效性/版本；notInterested与已完成/无效分别处理，更新去重。
8. **当前情境**：明确字段、来源、缺失、确认状态及更正方式。匹配指南证据与个人信息依据分别返回。

验收场景至少覆盖：

- 首次欢迎/跳过/完成；再次进入有内容、无推荐有话题、全空，三类不能相互误判。
- 自然输入与快捷场景只预填；空输入不可发，IME回车不误提交，长输入有上限反馈。

- 独立保存/调用开关的四种组合；关闭调用后不再展示引用但仍可查看已保存资料。
- 删除取消与确认、计数更新、关联引用失效；不删除其他类别和账号数据。
- 推荐有/无/加载/错误、依据修正和详情返回；反馈后状态一致，模拟不会调用外部搜索。

## 11. 04反馈流程的实施补充

新增04在本次捕获的范围内，用mock实现完整闭环，真实模式仅沿用现有guide反馈能力。

- D01–D04分别表达感兴趣、忽略、暂不关注。感兴趣不代表已执行；忽略和暂不关注不代表个人计划取消。不要用一个not_interested值假装三个语义全部已支持。
- D05–D07区分仅本次纠正和核对后长期更新；新旧值必须显示。关闭/取消对话框保持原长期档案。
- D08记忆更新成功与推荐重新判断分开反馈：前者成功后不因推荐失败而回滚或重复写记忆。
- D09–D11的联动结果分别处理仍相关、情境取消后暂无适合事项、关注反馈导致列表全空。空态说明原因，不能都叫“没有资料”。同一recommendation identity保持关注状态。
- D12明确失败恢复原关注状态；D13网络结果未知先查询结果，不能立即强行回滚或重复提交。真实端没有操作查询协议时只说明未知，等待后端补contract。
- D14长期记忆更新失败保留旧事实；用户可选择仅本次使用新更正；D15推荐更新失败保留已提交的记忆结果，单独重试推荐。
- 在mock加入operationId、confirmed/failed/unknown状态和readOperationResult方法，unknown场景可模拟查询后成功/失败。真实模式这只是缺口，不猜测新HTTP路径。

新边界：本轮不自动创建日程、待办或执行租房/合同操作。原型推荐是“关注事项与信息建议”；看过不等于做过，感兴趣不等于承诺执行。
