## 2. 我们在做什么

产品叫“苟活”，项目 / 仓库名 LifeOS。核心用途是：用户说出生活困扰或选择问题，产品结合用户明确提供的情境，在固定《HowToLiveBetter 高性价比人生指南》中寻找有出处的建议，并在用户允许的范围内记住生活信息、跟进问题进展。

当前要把这条任务跑通：

```text
一个生活问题
  → 输入 / 必要澄清 / 修正本次情境
  → 有来源和适用限制的指南回答
  → 可选核对个人信息
  → 仅本次使用，或确认保存长期生活事件
  → 查看 / 编辑 / 删除已保存资料
  → 再次咨询或 Radar 关注事项
  → 关注反馈与个人事实更正分开
  → 重新判断，失败时独立恢复
```

首版演示主线是“租房搬家”，另有“手机通知打断工作”固定指南示例。我们希望验证任务、信息边界与操作是否清楚；没有声称模拟版能理解任意问题、真实推荐或替用户执行事项。

原交接记录说明这是七人课程小组项目，用户负责前端，其他组员负责后端、原型/UI/交互、竞品及模型评测等。该协作背景在本轮没有重新确认，实际分工以团队最新信息为准。不要把本次前端接手扩大成重做后端或部署任务。

团队曾讨论复用 Proma Harness。**当前源码实际是 Python `AgentService`，没有已接入 Proma 核心的证据。** 该事项由后端确认；前端不直接接模型，不自行移植 Proma。旧 PRD 与旧远程站点可能滞后，不用它们覆盖当前用户决定。

## 9. 数据与业务规则

以下规则对修复和 UI 打磨都有效。

1. 本次情境、待确认候选、已保存长期事件是三种不同对象。核对之前不能增加长期计数；仅本次不进长期列表；保存成功才显示成功。
2. 更新保持同一 event id，用 version 校验。相同 requestId 重试应幂等；冲突先显示最新值与用户拟修改值，明确再次确认，不能盲覆盖。
3. 相对日期以发送时的 anchor 和 Asia/Shanghai 解释，保留 raw 与 precision。`2026-11` 是月精度，不补成某一天；刷新 / 继续聊不能把已确认日期重算。
4. 未提供预算、地区、合同阶段时保持未知。模拟使用明确 fixture，不把正则 / 默认值包装成真实 AI 理解。
5. allowSave / allowUse 独立。关闭保存不删除既有资料；关闭调用后仍可管理资料，回答 / 推荐不再引用。真实端当前 enabled 同时控制长期读写。
6. “感兴趣 / 忽略 / 暂不关注”是关注态度，不代表完成建议、解决问题或取消计划。看过不等于做过；done 反馈不自动改变个人事件状态。
7. 记忆写入成功与推荐重算独立。推荐失败保留已提交记忆与旧结果，旧结果标待更新；重试只重算推荐。
8. 技术失败、没有推荐、没有资料、知识不足、网络结果未知分别呈现。未知操作先查询同一 ID，不自动重复写入；真实端无查询协议就明确待确认。
9. 请求锁、loading、service generation / revision 和 app epoch 共同防陈旧回包。账号 / 模式 / 新话题 / 记忆变化不得让旧结果写回新状态。
10. 输入草稿、旧回答版本、失败候选要保留。快捷场景只预填；复制只有成功才提示成功。停止模拟保留部分文字，真实停止只中止浏览器等待。
11. 用户 / 模型文本纯文本渲染；指南字段和来源必须有实际依据。不实时读取外部网页时，不声称已经完成来源实时核验。
12. 模拟内容只在本次页面内存按账号维护；sessionStorage 只存欢迎偏好，刷新恢复虚构初始数据。无跨设备 / 跨刷新完整聊天持久化承诺。

当前模拟事件形状（示意，不是生产 HTTP 合同）：

```json
{
  "id": "mock-event-alice-move",
  "category": "生活事件",
  "eventType": "move",
  "title": "租房搬家",
  "status": "planned",
  "date": {
    "value": "2026-11",
    "precision": "month",
    "raw": "下个月",
    "anchor": "2026-10-14T07:00:00.000Z",
    "timezone": "Asia/Shanghai"
  },
  "attributes": {"housing": "rent", "budget": null},

```

长期分类入口为“生活事件 / 目标 / 偏好 / 经历”，当前主要有搬家事件。不要为了填满分类创造个人事实。

## 10. 真实 API 合同与缺口

真实请求走同源 `/api`，正式登录使用 HttpOnly Cookie；模型密钥、后端内部 token 不进入前端。

| 方法 | 路径 | 当前用途 |
|---|---|---|
| GET | `/health` | 进程与配置状态；不能证明模型可用 |
| POST | `/api/login` | `{username,password}` → 当前用户与会话 Cookie |
| POST | `/api/logout` | 撤销当前会话 |
| GET | `/api/me` | 当前用户 |
| GET | `/api/memories` | `{enabled,revision,memories,effective,feedback}`，长期摘要 |
| POST | `/api/memory-action` | settings / correct_summary / delete / clear / feedback |
| POST | `/api/run` | `{mode,query,conversation_id,followup_memory_id}`，一次性 JSON |
| GET | `/api/guide-entry?guide_id=...` | 已登录用户读取固定指南完整条目 |

`run.mode` 为 chat 或 home。chat 的 query 1–2000 字；结果状态 `answer/partial/unsupported/clarification/acknowledged`，最多 3 张后端核验指南卡片。典型回包有 `result`、`summary`、`conversation_id`；卡片含 `guide_id/title/fields/source_url/source_locator/match_reason/memory_ids`。兼容旧 result 字符串和 markdown，但不得造已验证来源。

home 仅返回未解决问题的 `result.followups`（含 memory_id、topic、progress_question、guide_question、guides），没有 Radar 建议正文。真实端关闭记忆停止长期读写 / 长期反馈；已有摘要仍可管理。

当前真实动作示意：

```json
{"action":"settings","enabled":true}
{"action":"correct_summary","id":"已有摘要ID","text":"1–800字","problem":"最多160字","user_state":"最多400字","problem_status":"unresolved"}
{"action":"delete","id":"已有摘要ID"}
{"action":"clear"}
{"action":"feedback","guide_id":"03-01","kind":"done"}
```

problem_status 枚举 `unresolved/resolved/unknown`；记录有效性 `active/superseded` 是独立维度。feedback 枚举 `done/not_interested/ineffective/undo`。当前真实 delete 和 clear 会清理该账号全部反馈，不能用模拟局部删除语义替代。HTTP 401 清除私有 UI；409 提示同用户上一任务仍在处理；网络失败不能断言服务器没收到。

SQLite 保存长期摘要，不保存完整逐字聊天。后端短期最近 6 轮、约 1 小时，重启清空；默认单 worker。真实取消浏览器请求不保证服务器取消。

待后端提供：候选提取与确认保存、结构化事件 / 分类 / 时间精度、expectedVersion 与幂等 requestId、独立开关、历史消息与回答版本、校验后的流式与取消回执、Radar 任务 / 依据 / 反馈查询、当前情境结构、局部删除语义。请沿用附件缺口表更新合成请求 / 响应、错误码与负责人；不要自行猜新 HTTP 路径，不能把 store 内部函数当公开 API。

## 11. 已确认的视觉与交互方向

当前用户明确要求是**极简、黑白灰**。以现有样式和最新截图继续，而非重新探索彩色主题。

- 白色页面与内容区，正文 / 主操作接近 `#171717`，辅助文字 `#666`，浅灰分隔 `#e7e7e7`，淡灰状态底。
- 小圆角 4–8px、轻边框、清楚留白；不增加大面积重阴影、渐变、装饰插画、彩色标签或复杂动效。
- 四区与模态保持同一组件层级；统一线性 SVG 图标，使用 currentColor。
- 常显必要的依据、未知条件、限制与关键操作，其余可展开。Figma 右侧逐步说明和总览标注是开发注释，不进产品正文。
- 错误 / 删除等操作可通过明确文字、字重、边框或确认步骤区分，不依赖红色；焦点为清晰黑色描边。
- 主要按钮触控高度至少 44px；320 起不横向溢出；桌面 Enter 发送、Shift+Enter 换行，IME 组合不提交；手机 Enter 换行。
- 模态支持 Tab / Shift+Tab 焦点限制、Escape 与关闭后恢复焦点；减少动效偏好生效。

## 12. 验收场景与完成标准

现有验收面板独立于产品正式运行：可切换 Alice / Bob、三种首页状态、问答延迟 450 / 1600 / 16000ms。故障场景持续生效，重试前选择正常；不要误把持续注入故障当新代码回归。

场景覆盖 normal、notification、clarification、partial、unsupported、network、error、nonjson、expired、busy、summaryfail、savefail、updatefail、conflict、deletefail、settingsfail、homefail、listfail、recommendfail、feedbackfail、unknown、unknownfail。`summaryfail` 在当前新模拟流程是候选整理失败，不是后端自动摘要真实验收。

下一版必须检查：

| 路径 / 条件 | 必须可观察的结果 |
|---|---|
| 首次 / 再次进入、跳过 / 回看、三种首页 | 有推荐、有话题、全空不混淆；错误不伪装空态 |
| 快捷场景 → 编辑 → 发送 | 不点击即发；问题保留，前文不被覆盖 |
| 推荐 15-01 与 04-18 → 条件 / 继续聊 / 返回 | 推荐身份、指南对象与本次依据保持一致 |
| 澄清补充 / 跳过、本次修正 | 仅更新明确值；未知保持未知；不反复强迫补充 |
| 模拟分段 / 停止 / 失败 / 重试 / 版本 | 保留部分文字、旧版与新草稿；同轮重试不重复追加用户问题 |
| 候选 → 仅本次 / 长期保存 | 确认前计数不变；仅本次不进长期；重复确认不重复建 |
| 新话题 / 恢复话题 / 账号切换 | 临时信息不跨错误边界；合理导航返回保留当前草稿 |
| 编辑、冲突、保存 / 更新失败 | 同 id 更新，冲突必须选择，旧值 / 候选 / 编辑输入保留 |

| 删除取消 / 确认、分类与引用 | 取消不变；计数与关联引用更新；不删其他账号 |
| 已保存记忆 + 推荐失败 | 保留已提交结果和待更新旧推荐，仅重试推荐 |
| 两个 unknown 反馈与明确失败 | 每次操作可查询，成功 / 失败 / 未知区分，不重复提交 |
| 401 / 409 / 网关 HTML / 网络 / 二次列表失败 | 私有显示清理、等待可读、失败独立恢复，不重跑成功问答 |
| 四区 320 / 390 / 760 / 1440、窄屏模态 | 无横向溢出，输入 / 按钮可用，黑白灰一致 |
| 键盘、焦点、屏幕阅读顺序、纯文本 | IME 不误发，模态可退出，HTML 字样不执行，阅读不被流式重绘打断 |
